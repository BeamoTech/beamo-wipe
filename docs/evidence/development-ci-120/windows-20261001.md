## Follow-up changes

The advertised `dev.py test --native` initially failed: **49 passed, one skipped,
three failed**. Inspection isolated two native Windows file-handling problems
in `scripts/build_desktop.py`:

- For unchanged `desktop/GO-LICENSE.txt`, path stat and descriptor stat reported
  identical file ID, size and modification time but different change-time
  values. Compare change time before/after using each matching API; POSIX
  retains the additional cross-API comparison. File identity, type, size,
  modification time and exact read length checks remain required.
- Windows refused deletion of the build lock while its handle was open. Close
  that handle, then recheck the original lock file ID and every output path
  component before removal. Preserve a substituted lock or output directory.
  POSIX retains descriptor-relative removal while its handle is held.

Portable regressions cover Windows/POSIX timestamp rules, mutation during read,
successful/failed cleanup, reuse and substituted lock/directory preservation.
Initial lock inspection is inside the cleanup scope: a transient inspection
error retries while the original handle is held, then closes all handles and
removes only an identified owned lock. Persistent unknown identity retains the
lock, without a success receipt, for manual inspection. Existing success and
failure tests now require lock cleanup. The guide links these dated results and
describes qualification doctor precisely: Git and optional gh discovery, without
probing the selected Python environment or credentials. Doctor code and all
legacy compatibility behavior are unchanged in this follow-up.
