## Proven finding and narrow fix

The streaming completion projection classified summary rows and separators
from their raw text, while the structured engine check parser first removes
an engine timestamp/level prefix. Therefore a prefixed flagged shortfall row
(`info: ! sda | 1 | 2 | 50.00%`) disappears from a large log's assessment.
With a genuine `No hidden sectors on /dev/sda` record, the advisory incorrectly
changes from warning to pass. A prefixed malformed row similarly changes
unavailable to pass. A dropped prefixed closing separator moves a later row
inside the summary and changes pass to unavailable. These advisory changes do
not change the independently validated completion outcome.

The original concrete 10-case fake-process poll trace is in
`projection-summary-original.json`, generated by `projection-summary-trace.py`.
Every trace compares direct/full parsing against the runner's assessment and
hashes the log before/after. All small controls agree; the three large variants
above disagree. Exact starting sources are `nwipe_runner-start.py` and
`engine_checks-start.py`.

The authorized fix computes the existing `_engine_log_body(line)` once per
scan record and uses it for summary close/context tracking, separator retention
and target row retention. The projection still stores the exact original
record. Completion parsing, CR provenance, terminal evidence rules, scan limits,
and the existing pass 8 progress insertion/order fix remain intact.
