Problem: live asset staging accepts a non-executable shipped kiosk supervisor.
The systemd unit directly executes /usr/local/sbin/beamo-wipe-kiosk. Its working
file can lose mode 0755 -> 0644 (for example on a checkout with core.filemode=false)
without Git exposing a mode diff. stage_assets explicitly requires executable
/usr/local/bin/beamo-wipe and the nwipe hook, but never checks the supervisor.
It therefore succeeds and rsync -a preserves a supervisor the kernel cannot exec.
This breaks automatic wizard startup and the supervisor-provided fallback menu.

Proof:

  python /workspace/beamo-tools/audit-20261019/boot-build/reproduce_kiosk_mode.py

kiosk-mode-reproduction.json. Both controls keep index mode 100755 and have no
working-tree mode diff with core.filemode=false. Staging rc=0 with modes0755 and0644.
All fixtures are regular files in this audit directory, with mocked build identity;
no kiosk, disk, firmware, restart, Docker, guest, or privileged process is executed.

Related gap: live_build_inputs binds bytes and node type but not modes.
The copied-tree digest remains unchanged after a copied kiosk chmod0755->0644;
a normal tree matches and a byte-change control mismatches as expected. The copy
check cannot detect that particular divergence after stage_assets returns.

Proposed narrow B1 fix: require_executable for the kiosk alongside the existing
entrypoint/hook checks in scripts/stage_live_assets.py; add an execute-the-real-
stager regression in tests/test_iso_live_assets_pass20.py with0755 normal control
and0644 rejection. Metadata binding in release_manifest can be assessed separately
because changing its input inventory affects provenance format and existing tests.
