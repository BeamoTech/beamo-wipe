## Console diagnostic transition

The one-line `inventory_open = False` executes immediately after the existing
available diagnostic shortcut calls `wizard.open_diagnostic()`, before the next
render/input cycle. `_loop` renders inventory ahead of screen-specific content,
so clearing this rendering owner makes the next frame show diagnostic notice
and preparation instructions that agree with already-selected DIAGNOSTIC state.
It follows the existing refresh-shortcut ownership pattern. Other overlay flags
are consulted only while inventory_open is true; their later opening paths
explicitly reinitialize comparison/boot mode, so retaining them here is harmless.

## GTK accepted output rollback

- `_chosen_radio` records the exact widget tied to the accepted output ID during
  initial discovery, and tracks the new widget only after successful selection.
  Repeated human-readable labels cannot confuse object-identity restoration.
- `_restore_output_choice()` wraps synchronous `set_active(True)` in a try/finally
  `_restoring_output` guard. Both active/idle toggles generated by GTK are guarded;
  inactive callbacks are also independently ignored. Restoration cannot enqueue
  a replacement audio job or reapply an old sink merely to repair the radio UI.
- Failed SoundResult restores the accepted radio in its done callback. Worker
  exceptions, cancelled values and timeout errors take the generic poll branch,
  which restores it too. In each path restoration/announcement precedes the
  moved `_busy(False)`, so controls are reenabled after visible and accepted
  selection agree. Failed selection leaves `chosen` and Wizard.sound_output
  unchanged; volume and mute still address that accepted sink.
- Success updates Wizard.sound_output, `chosen`, and `_chosen_radio` together in
  the UI completion callback before controls are reenabled. Existing worker I/O
  stays outside GTK/Wizard mutations. Initialization's programmatic selection
  connects each new choice after set_active; prior choices emit inactive toggles,
  so initialization does not launch unintended output changes.
- `_destroyed()` cancels and clears the ticket/callback and accepted-radio widget.
  `poll()` first rejects a destroyed dialog, or closes on screen/epoch change.
  A late worker completion cannot apply accepted/Wizard selection after close.
- Generic failure rollback is harmless for volume/mute/play operations because
  their visible output choice already matches the stored accepted widget.

Reviewed all11 new GTK tests: one5way success/refusal/exception/timeout/cancel
selection+following-control agreement test; four same-radio retries; close with

The guard is additionally substantiated by asserting only the attempted set call,
so restoration cannot silently generate another set_output operation.
