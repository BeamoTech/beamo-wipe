# Physical test matrix (#116)

Every row is a test on **real hardware**. Every row starts **NOT TESTED**.
Read the [packet README](README.md) first. It has the safety rules, the
result words and the order of work.

`matrix.csv` holds the same rows for a spreadsheet. Keep the two files the
same. `tests/test_physical_acceptance_116.py` fails when they differ, when a
row has no ID or status, or when a Pass row has no run record and evidence.

## How to fill a row

1. Run the row's procedure. Fill a [test run record](forms/test-run-record.md).
2. Change **Status** to one result word: Pass, Fail, Excluded, BLOCKED or
   Unknown. Leave NOT TESTED if the row did not run.
3. For Pass, Fail and Unknown, add the run ID and the evidence file names
   to the end of **Evidence required**, like this:
   `run: RUN-20270115-01; logs/PHY-DELL-02-boot-20270115T101500Z.txt`.
4. Never fill a cell from the last column. That column lists virtual and
   CI evidence that already exists. It never counts as a physical result.

One computer can cover many rows. A Pass covers only the named computer,
firmware version, disk and image. It does not carry over to another model.

Notes on overlap:

- A PHY-ERASE Pass for a method may be cited as the PHY-DEST row for that
  method. Use the same evidence. Do not run the erase twice.
- The #111 firmware sheet says "HP F9 or Esc" and "ASUS F8/Esc". It predates
  the one key table (#184). The current keys are in `desktop/bootkeys.json`
  and in the PHY-<brand>-01 rows below. Judge the key against that table.
- PHY-PWR rows test power without an erase. PHY-INT rows test power
  during an authorized erase.
