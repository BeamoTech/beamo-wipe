# Beamo Wipe bug audit — 2026-09-26

Base: `4feb25a` (`v0.2.10`). This pass used fake devices and UI test doubles;
no physical disk was erased and no release was published.

## Reproduced and fixed

1. After the Tk view handed off to the accessible view, choosing another disk
   created a new session with `reader=None`. The accessible startup stages
   therefore ran before Orca started, leaving discovery silent for a screen
   reader user. The session loop now starts and owns a reader before those
   stages. A portable regression failed before this change and passed after.
2. A reader process that exited between sessions was still passed to the next
   accessible startup. The session loop now checks its process status and
   starts a replacement before discovery. A separate regression failed before
   this change and passed after. The loop stops readers it started when it
   exits; an initially supplied reader remains owned by its caller.

## Verification and limits

- The full supported local Python suite passed after refreshing the ignored
  live-build staging copy of `app.py`. Five previously documented host-specific
  tests were deselected: two require Linux GTK/ATK, two need headless Chrome
  access denied by this sandbox, and one needs a Unix-socket bind denied here.
  The unrestricted run failed at those same five tests before this change.
- The focused new regressions and neighboring new-session tests passed. Ruff,
  Python compilation, ShellCheck, fake-device preview entry points, the
  staged-source match, and `git diff --check` passed.
- A nonpublishing hosted Linux check was attempted with
  `./scripts/ci-cloud.sh --skip-iso`, but `gcloud` could not refresh its
  credential noninteractively. It submitted no build. Hosted GTK validation
  remains unobserved for this change. No ISO/x86 build behavior changed.

A follow-up review of disk selection, nwipe completion, report export,
build/release boundaries, and session transitions found no further actionable
defect in this checkout. This observation is limited to the inspected code and
tests, not a claim that all hardware and user paths are bug-free.
